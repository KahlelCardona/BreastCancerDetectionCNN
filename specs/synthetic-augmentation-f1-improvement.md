## Purpose / Big Picture

The prior plan tried one specific way to reduce overfitting and raise F1 (a single number combining precision — how many of a model's "Malignant" calls were correct — and recall — how many of the truly malignant images a model actually caught): adding ~2,770 real cropped-patch images, close-up photographs of the same lesions already present in the full mammograms. That did not work: measured honestly on the same untouched 704-image held-out test set used throughout this project, ResNet ended at F1 0.6504 (essentially flat versus its original 0.6534) and EfficientNet ended at F1 0.6290 (worse than its original 0.6375). The likely reason, reasoned out at the end of that plan: a cropped patch and its parent full image are not independent information — they show the exact same lesion at two zoom levels — so adding them let both models get better at recognizing specific lesions they had already partly seen (validation F1 rose to 0.65-0.75), without teaching them to generalize better to genuinely new, unseen patients (test F1 stayed at 0.55-0.65 the whole time).

This plan tests a different lever for the same goal: instead of adding more (closely-related) real images, it makes the randomized image transformations already applied to every training image more varied, so the model sees a different randomized version of each of the same 2,864 original training images on every pass, forcing it to rely less on exact pixel positions, lighting, and framing. It also reverts the dataset back to exactly its original composition (full images only, no cropped patches) so that if F1 changes, it can only be attributed to the strengthened transforms, not a mix of two different changes at once. Concretely, after this plan: running `py evaluate.py --model resnet --checkpoint <winning checkpoint(s)> --tta --threshold <winning threshold>` will print an accuracy/precision/recall/F1 line for ResNet on the same 704-image held-out test set, and the same for EfficientNet, and this document will state plainly whether either number beats that architecture's original baseline (ResNet F1 0.6534, EfficientNet F1 0.6375) — genuinely not guaranteed, exactly as every step of this project so far has been measured and reported honestly rather than assumed. The live web app (`py app.py`) will keep working exactly as today; `eval_results/selected_models.json` is only updated for an architecture if this plan's own result actually beats that architecture's original baseline, otherwise that architecture's entry is left exactly as the crop-augmented plan left it.

## Decision Log

- Decision: revert the cropped-patch dataset augmentation entirely for this experiment (both training scripts go back to constructing `MammogramRawDataset(["mass_train", "calc_train"])` with no `include_cropped_patches` argument, and back to plain `StratifiedKFold` instead of `StratifiedGroupKFold`) rather than layering the new, strengthened transforms on top of the crop-augmented dataset.
  Rationale: the repository owner chose this directly when asked, specifically to isolate whether stronger synthetic augmentation helps, uncontaminated by the crop-augmentation change that the prior plan already measured as not helping (and, for EfficientNet, measurably hurting). Reverting the fold-splitting method too, not only the data-inclusion flag, avoids relying on an assumption that `StratifiedGroupKFold` with every sample in its own singleton group produces the same fold partition as plain `StratifiedKFold` with the same seed — the two are different algorithms internally and are not guaranteed to agree bit-for-bit, so an exact revert is used instead of an assumed equivalence.
  Date/Author: 2026-08-27, drafted by agent per the repository owner's direct instruction ("strengthen the augmentation and remove the cropped images").
- Decision: strengthen `DataSetAugmentation.py`'s `get_train_transforms()` to the "moderate" of two proposed strengths: replace `RandomRotation(10)` with `transforms.RandomAffine(degrees=15, translate=(0.1, 0.1), scale=(0.9, 1.1), shear=5)`; widen `ColorJitter` from `brightness=0.2, contrast=0.2` to `brightness=0.25, contrast=0.25`; and add `transforms.RandomErasing(p=0.3, scale=(0.02, 0.15))` as a new final step after `Normalize`. ## Plan of Work

### Milestone 1 — revert to full images only, strengthen the transform pipeline

In `DataSetAugmentation.py`, change `get_train_transforms()` to: keep `Resize((Config.IMAGE_SIZE, Config.IMAGE_SIZE))` and `RandomHorizontalFlip(p=0.5)` exactly as they are; replace the `RandomRotation(10)` line with `transforms.RandomAffine(degrees=15, translate=(0.1, 0.1), scale=(0.9, 1.1), shear=5)` (one randomized transform that rotates by up to ±15 degrees instead of today's ±10, additionally shifts the image by up to 10% of its width/height, zooms it in or out by 90%-110%, and shears it by up to 5 degrees — all four effects are re-randomized independently on every single access of every image, so the same training image looks meaningfully different on every epoch); widen `ColorJitter` from `brightness=0.2, contrast=0.2` to `brightness=0.25, contrast=0.25`; keep `ToTensor()` and the existing `Normalize(...)` call exactly as they are; and add one new final step, `transforms.RandomErasing(p=0.3, scale=(0.02, 0.15))`, placed after `Normalize` (this randomly blanks out one rectangular region covering 2%-15% of the image's total area, on 30% of training accesses — a technique commonly called "cutout" — which prevents the model from being able to rely too heavily on any single localized patch of the image always being present and informative). Do not change `get_val_transforms()` at all; it must keep returning only `Resize`, `ToTensor`, `Normalize`, with zero randomness, since validation and the held-out test set must never be randomly augmented — this is unchanged from every prior plan.

In `ResNet.py`'s `main()`, change `raw_dataset = MammogramRawDataset(["mass_train", "calc_train"], include_cropped_patches=True)` to `raw_dataset = MammogramRawDataset(["mass_train", "calc_train"])` (simply omitting the argument, which defaults to `False`, exactly restoring the original pre-prior-plan call); change the import line `from sklearn.model_selection import StratifiedGroupKFold` back to `from sklearn.model_selection import StratifiedKFold`; change `skf = StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=42)` back to `skf = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)`; and change `skf.split(np.zeros(len(labels)), labels, groups=raw_dataset.groups)` back to `skf.split(np.zeros(len(labels)), labels)`.
